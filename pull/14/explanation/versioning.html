Versioning and release

This document semi-formally explains the versioning scheme and process used for the components and resulting binaries of the ad_r1m_ros2 repo. Extra care is needed because this one repo generates multiple kinds of packages, with slightly diverging versioning conventions. This has been designed on a best-effort basis SHOULD be revised if deemed unsuitable, to eliminate any need to bypass it.

All components’ versions MUST be kept in sync at each release, even if some components don’t change between versions.

Release X.Y.Z(-W) MUST directly map to git tag X.Y.Z(-W), in which all components’ sources MUST reflect version X.Y.Z(-W) (optionally truncated to X.Y.Z where no suffix is allowed).

In between releases, CI runs nightly builds, useful for development and evaluation. One of the main challenges this document addresses is sanely representing the intermediate version state in nightly builds without clashing with main releases. Disambiguating between intermediate versions SHOULD be automated based on the git history (see git describe). Some components types can’t represent intermediate versions properly.

Version increment process

Implementing a single source of truth repo-wide would require at least some form of a templating system (at the very least for the ROS package.xml files) which we deem counterproductive. Therefore, the diff for a version increment touches a number of files, while making sure to keep them all in sync.

For the following examples, say we are incrementing from version 1.2.3 to 1.2.4 on 2026-12-25.

Increment ROS versions:

  1. In all ROS package.xml files, increment <version> tag to 1.2.4

  2. In all ROS CHANGELOG.rst files, rename the “Forthcoming” header to “1.2.4 (2026-12-25)” and prepend an empty section with a new “Forthcoming” header, e.g.:

      Forthcoming
  -----------
+
+ 1.2.4 (2026-12-25)
+ ------------------

  * Ho Ho Ho
  * Happy Holidays!

  1.2.3 (2020-05-06)
  ------------------

  ...

Increment Debian package version: In packaging/debian, use dch to automatically edit the changelog file, e.g.:

~/ad-r1m-ros2/$

cd packaging

~/ad-r1m-ros2/packaging$

export DEBFULLNAME="Santa Claus"

~/ad-r1m-ros2/packaging$

export DEBEMAIL="santa.claus@lapland.com"

~/ad-r1m-ros2/packaging$

dch --release --distro trixie

Commit, tag, push new version:

~/ad-r1m-ros2/$

git add .

~/ad-r1m-ros2/$

git commit -sm 'Release 1.2.3'

~/ad-r1m-ros2/$

git tag 1.2.3

~/ad-r1m-ros2/$

git push

~/ad-r1m-ros2/$

git push --tags
